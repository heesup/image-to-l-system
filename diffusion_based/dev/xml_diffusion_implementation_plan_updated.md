# 3D Plant Organ Part Diffusion Model Implementation Plan

## Executive Summary & Objectives

The goal is to upgrade the 3D plant graph diffusion framework (`PlantGraphDiffuser3D`) to reconstruct realistic 3D plant architectures directly from 2D observation images.
The dataset will transition from simple procedural 3D graphs to high-fidelity **Helios L-System XML architectures** generated by the `./main` binary (`syntheticdata_generation`).

Key technical updates include:
1. **Extended Organ Representation (15D)**: 4 organ classes (`internode`, `petiole`, `leaf`, `floral_bud`) with organ-specific geometric attributes.
2. **Hierarchical Shoot-Phytomer Topology**: Modeling parent-child node dependencies within and across shoot levels.
3. **PyTorch Differentiable Soft Renderer**: Projecting 3D predicted organ meshes/primitives into 2D soft silhouettes/images to enforce direct 2D image reconstruction loss $\mathcal{L}_{\text{render}}(\hat{I}_{2D}, I_{2D})$.
4. **Automated Helios Dataset Pipeline**: Batch generating paired JPEG images and XML files across days-after-planting (DAP) 5–60.

## Architectural & Technical Detailed Answers

### 1. Organ Attribute Decomposition (Option B) & Shoot Hierarchy (Option C)

#### A. Unified Node Feature Vector $\mathbf{x}_i \in \mathbb{R}^{15}$
Each node $i \in \{1, \dots, N\}$ in set $V$ is represented as a 15-dimensional continuous vector:

$$\mathbf{x}_i = \big[\, x, y, z, \; l, r, \; \theta_{\text{pitch}}, \phi_{\text{yaw}}, \psi_{\text{roll}}, \; \mathbf{c}_{\text{type}} \in \mathbb{R}^4, \; s_{\text{shoot}}, d_{\text{phytomer}}, e_{\text{exist}} \,\big]$$

| Index | Attribute | Description | Organ-Specific Mapping |
|---|---|---|---|
| `0..2` | `x, y, z` | 3D Root/Base Position | Global 3D Euclidean coordinates |
| `3` | `l` | Length / Scale | Internode/Petiole length, Leaf scale, Peduncle length |
| `4` | `r` | Radius / Thickness | Internode/Petiole radius, Peduncle radius, Leaf width ratio |
| `5..7` | `pitch, yaw, roll` | 3D Euler Orientations | Local rotation angles in degrees |
| `8..11` | `organ_type` (One-Hot) | 4-Class Categorical | `[0]` Internode, `[1]` Petiole, `[2]` Leaf, `[3]` Floral Bud |
| `12` | `shoot_id` | Shoot Hierarchy ID | Trunk shoot (0), Lateral shoots (1..3) |
| `13` | `phytomer_idx` | Phytomer Index | Sequential phytomer node along shoot stem |
| `14` | `existence` | Confidence Score | $[0, 1]$ active vs pruned node mask |

#### B. Hierarchical Topology (Shoot-Phytomer Tree Structure)
- **Helios Graph Model**: Plant $\rightarrow$ Shoots $\rightarrow$ Phytomers $\rightarrow$ (Internode, Petiole, Leaf, Floral Bud).
- **Topology Prediction**:
  - The model outputs pairwise parent logits $P_{ij} \in \mathbb{R}^{N \times N}$.
  - During k-NN spatial candidate selection ($k=16$), parent candidate scoring incorporates hierarchical constraints: internodes connect sequentially along the shoot axis, petioles attach to internode nodes, and leaves/buds attach to petiole tips.

---

### 2. PyTorch Differentiable Renderer vs. Helios C++ Simulator

#### A. Role Separation
- **Helios C++ (`./main`)**: Used **offline as the ground-truth data engine**. It renders photorealistic JPEG images $I_{2D}$ using OptiX ray tracing and exports exact 3D plant structures $G_{3D}$ in XML format.
- **PyTorch Differentiable Renderer (`DifferentiablePlantRenderer3D`)**: Runs **online inside PyTorch autograd backprop loop**.

#### B. Differentiable Soft Polygon & Cylinder Rasterization Mechanism
1. **3D Mesh Generation from Predicted Nodes**:
   - Internodes & Petioles $\rightarrow$ 3D Soft Cylinders / 3D Line Segments projected via camera matrix $\mathbf{P}_{\text{cam}}$.
   - Leaves $\rightarrow$ 3D Cordate Polygons (Heart shape) oriented via predicted $(\theta, \phi, \psi)$.
   - Floral Buds $\rightarrow$ 3D Spherical/Ellipsoidal Soft Blobs.
2. **Perspective Camera Projection Matrix**:
   $$[u_i, v_i, w_i]^T = \mathbf{K} [\mathbf{R}_{\text{cam}} \mid \mathbf{t}_{\text{cam}}] [x_i, y_i, z_i, 1]^T, \quad (p_x, p_y) = (u_i / w_i, v_i / w_i)$$
3. **Soft Distance Falloff (Sigmoid Rasterization)**:
   $$\hat{I}_{2D}(x, y) = 1.0 - \prod_{k=1}^N \left( 1 - \sigma\left( \frac{r_k - d((x,y), \text{proj}(organ_k))}{\tau} \right) \cdot e_k \right)$$
4. **Image Loss Functions**:
   $$\mathcal{L}_{\text{render}} = \|\hat{I}_{2D} - I_{2D}\|_1 + \lambda_{\text{SSIM}} (1 - \text{SSIM}(\hat{I}_{2D}, I_{2D})) + \lambda_{\text{IoU}} (1 - \text{IoU}(\hat{S}_{2D}, S_{2D}))$$

---

### 3. Floral Bud Handling (Q3)

- `organ_type[3]` is explicitly reserved for **Floral Bud** (Peduncle + Bud/Inflorescence).
- In early growth stages (e.g. DAP 5–15), floral bud features act as placeholder nodes (`existence -> 0` or default parameters).
- In later growth stages (DAP 20+), peduncle length, radius, and bud state are populated from XML parser.
