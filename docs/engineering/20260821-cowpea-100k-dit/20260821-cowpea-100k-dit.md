## 4. 26D Node Vector Encoding (Key Data Format)

Each plant organ is represented as a **512 slots × 26 dimensions** tensor:

```
Dim  0..11: One-hot organ category (12 classes)
             0=Root Meta, 1=Shoot Meta, 2=Internode, 3=Petiole,
             4=Leaf, 5=Bud, 6=Peduncle, 7=Flower, 8=Fruit/Pod,
             9=Flower Closed, 10=Bud Aborted, 11=Empty
Dim 12..14: Base position (x, y, z) normalized by / 20.0
Dim 15..20: 6D continuous rotation matrix (R_6D)
Dim 21..23: Scale (sx, sy, sz) normalized by / 50.0
Dim     24: Curvature normalized by / 100.0
Dim     25: Phyllotactic angle normalized by / 180.0
```

## 7. Known Issues & Operational Notes

| Issue | Details | Solution |
|-------|---------|----------|
| **Helios C++ Binary Requires GPU** | Raw Helios engine (`submodules/Digital-Crops/.../main`) requires NVIDIA OptiX/CUDA | Run only on GPU nodes (`gres=gpu:1`) |
| **PyTorch Renderer CPU Fallback** | `HeliosPyTorchRenderer` defaults to slow software rasterization without GPU | Always pass `--device cuda` |
| **`canonical_cowpea_dataset.py` Slot Indexing** | Encoded with `max_slots=512` | Maintain `max_slots=512` |
| **Checkpoint Management** | `fm/part_flow_matching_epoch*.pt` (1.1GB × 60 = 66GB) | Retain only latest and best checkpoints |
| **Canonical Slot Ordering** | Sorting slots by organ_type improves training stability | Implement sort by organ_type in dataset |
