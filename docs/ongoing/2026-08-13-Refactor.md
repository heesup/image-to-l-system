# 2026-08-13 PlantOrganArray Refactor Plan

## Goal
Replace the `(N, 94)` PlantOrganArray tensor with a smaller, typed, per-organ-row representation that:
1. Reduces feature dimensionality.
2. Uses a **categorical** organ type (not one-hot).
3. Only shares columns when fields have the same physical meaning.
4. Supports **honest XML round-trip** without saving raw XML text verbatim.
5. Keeps the legacy 94D layout as a deprecated compatibility bridge.
6. Does not break PyTorch rendering.

---

## 1. Why the current 94D layout is problematic

- Many repeated parameter blocks (internode, petiole0, petiole1, leaves, flowers).
- Fixed phytomer slots waste dimensions on organs that are absent.
- `shoot_type_label` and parent indices are stored per-phytomer even though they are per-shoot.
- Constants such as radial subdivisions, length segments, and taper are learned as free scalars even though they are often dataset-specific.

---

## 2. New tensor layout: `(N, 40)` per-organ row

Each row represents **one organ instance** or the plant/shoot metadata root.

| Col | Name | Physical meaning | Used by |
|-----|------|------------------|---------|
| 0 | `plant_id` | Plant instance ID | all |
| 1 | `plant_age` | Plant age | all |
| 2 | `base_x` | Plant base position X | ROOT_META |
| 3 | `base_y` | Plant base position Y | ROOT_META |
| 4 | `base_z` | Plant base position Z | ROOT_META |
| 5 | `shoot_id` | Shoot ID | all |
| 6 | `parent_shoot_id` | Parent shoot ID | all |
| 7 | `parent_node_idx` | Parent phytomer index | all |
| 8 | `parent_petiole_idx` | Parent petiole index | all |
| 9 | `phytomer_idx` | Phytomer index along shoot | all |
| 10 | `child_index` | Leaf / flower / bud / petiole index within parent | all |
| 11 | `organ_type` | Categorical int: 0=ROOT_META, 1=INTERNODE, 2=PETIOLE, 3=LEAF, 4=BUD, 5=PEDUNCLE, 6=FLOWER | all |
| 12 | `shoot_type` | 0=unifoliate, 1=trifoliate | per-shoot |
| 13 | `length` | Tube length (internode / petiole / peduncle) | 1,2,5 |
| 14 | `radius` | Tube radius (internode / petiole / peduncle) | 1,2,5 |
| 15 | `scale` | Overall scale (leaf scale / flower base scale) | 3,6 |
| 16 | `pitch` | Rotation around lateral axis | all |
| 17 | `yaw` | Rotation around vertical axis | all |
| 18 | `roll` | Rotation around longitudinal axis | all |
| 19 | `curvature` | Tube bending (petiole / peduncle) | 2,5 |
| 20 | `phyllotactic_angle` | Internode twist around stem | 1 |
| 21 | `length_max` | Maximum internode length | 1 |
| 22 | `length_segments` | Discretization segments (internode / petiole) | 1,2 |
| 23 | `curv_pert_0` | Curvature perturbation sample 0 | 1 |
| 24 | `curv_pert_1` | Curvature perturbation sample 1 | 1 |
| 25 | `yaw_pert_0` | Yaw perturbation sample 0 | 1 |
| 26 | `yaw_pert_1` | Yaw perturbation sample 1 | 1 |
| 27 | `current_leaf_scale_factor` | Petiole-driven leaf scale | 2 |
| 28 | `taper` | Petiole radius decay | 2 |
| 29 | `radial_subdivisions` | Petiole cross-section resolution | 2 |
| 30 | `leaflet_scale` | Compound leaflet scale | 2 |
| 31 | `leaflet_offset` | Compound leaflet offset | 2 |
| 32 | `bud_state` | Floral bud state | 4 |
| 33 | `bud_parent_index` | Bud parent index | 4 |
| 34 | `bud_is_terminal` | Bud terminal flag | 4 |
| 35 | `fruit_scale` | Bud/flower fruit scale | 4,6 |
| 36 | `flower_azimuth` | Flower azimuth | 6 |
| 37 | `flower_offset` | Inflorescence offset | 6 |
| 38 | `reserved` | Reserved | all |
| 39 | `existence` | Per-organ existence probability | all |

### Column sharing rules
- `length`, `radius`, `scale` are **not** shared across different geometry semantics.
- `pitch`, `yaw`, `roll` share columns because they are all Euler rotations with the same physical meaning.
- `curvature` is shared by petiole and peduncle because both bend a tube.
- Unused columns for a given organ type are zero-filled.

## 3. Honest XML round-trip strategy

No raw XML text is stored in `raw_metadata`. The XML writer reconstructs tags by:
1. Grouping organ rows by `(plant_id, shoot_id, phytomer_idx)`.
2. Emitting the plant header from the ROOT_META row.
3. Emitting shoot tags from the first internode row of each shoot.
4. Emitting `<internode>` from the internode row.
5. Emitting `<petiole>` rows in `child_index` order.
6. Emitting `<leaf>` rows under the correct petiole by `parent_petiole_idx` and `child_index`.
7. Emitting `<floral_bud>`, `<peduncle>`, and `<flower>` rows similarly.

`raw_metadata` may still hold derived string artifacts (e.g. formatting helpers) but the **tensor itself is sufficient for lossless reconstruction**.

---

## 4. Legacy 94D bridge

- Keep the existing 94D constants and `from_xml_string()` / `to_xml_string()` path.
- Mark with deprecation comments: `# LEGACY 94D — scheduled for deletion after migration`.
- Add conversion methods:
  - `PlantOrganArray.to_legacy_tensor()`
  - `PlantOrganArray.from_legacy_tensor(tensor, raw_metadata)`
- New default methods:
  - `from_xml_string_typed(xml)` → returns 40D object.
  - `to_xml_string_typed()` → writes XML from 40D tensor.

## 7. Expected outcomes

- Dimension reduced from **94 → 40** (57% reduction).
- Organ type is a categorical integer, consistent with other ID fields.
- XML round-trip remains lossless without verbatim XML caching.
- Rendering remains pixel-identical to legacy path.
- Diffusion model inputs become more semantically meaningful.
