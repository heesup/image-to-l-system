# 3D Plant Organ Part Diffusion Model Update Plan

## Background & Objectives

Currently `PlantGraphDiffuser3D` is trained on **pure procedural synthetic data** (`Plant3DDataset`).
However, `cowpea_0000_plant_0000.xml` (Helios XML) contains **authentic botanical structures** generated by the physical L-system simulator:

| Observation | Current | Target |
|---|---|---|
| Data Source | Manual procedural generation (`Plant3DDataset`) | Helios XML → authentic botanical morphology |
| Organ Representation | 7D single primitive (x,y,z,θ,φ,len,is_leaf) | Phytomer-hierarchy-based multi-organ types |
| Topology | Simple 3-level tree | Shoot-Phytomer-Internode-Petiole-Leaf hierarchy |
| Training Data | Fixed 4 samples | XML batch loader, DataLoader batch training |
| Image Conditioning | Synthetic rendering | Helios rendered JPEG + XML pairs |

---

## Open Questions

> [!IMPORTANT]
> **Q1: Organ Representation Granularity**
> The XML schema includes multiple organ types: `internode`, `petiole`, `leaf`, `floral_bud`, etc.
> To what dimensionality should the 7D vector be extended?
> - (A) Retain 7D base + organ_type one-hot (4 types: internode/petiole/leaf/floral_bud) → 11D
> - (B) Organ-specific attributes (internode: length+radius+pitch; leaf: scale+pitch+yaw+roll)
> - (C) Explicitly model shoot-level structure as a graph hierarchy

> [!IMPORTANT]
> **Q2: Real Image-XML Pair Dataset Scale**
> Currently 1 pair exists (`cowpea_0000_vis.jpeg` + `cowpea_0000_plant_0000.xml`).
> What DAP range and sample scale should be generated for training?
> - E.g. DAP 5–60 days, N samples per DAP (varying seeds/parameters)
> - Continue supplementary training on 100 synthetic samples or switch exclusively to XML?

> [!NOTE]
> **Q3: Floral Bud Handling**
> XML includes `floral_bud` (peduncle + inflorescence) at DAP 10 (no fruit).
> Decide whether to model floral buds as distinct organ types or disregard them.

## Proposed Changes

### Component 1: XML Parser & Real Dataset Pipeline

#### [NEW] `dataset/helios_xml_parser.py`
Parse Helios XML into organ-level graph representation:
- `parse_helios_xml(xml_path)` → parse shoot, phytomer, and node hierarchy
- **Organ Type Mapping**: `internode(0)`, `petiole(1)`, `leaf(2)`, `floral_bud(3)`
- **Node Feature Vector (11D)**:
  - `x, y, z` (3D world coordinates via forward kinematics)
  - `length` (internode_length / petiole_length / leaf_scale / peduncle_length)
  - `radius` (internode_radius / petiole_radius)
  - `pitch, yaw, roll` (organ orientation)
  - `organ_type` (4D one-hot or 4D softmax)
- **Topology**: Tree adjacency matrix mapped from parent shoot ID → parent node

```
Helios XML Hierarchy:
plant_instance
  └─ shoot[0] (unifoliate)
       └─ phytomer → internode → petiole(s) → leaf(s)
  └─ shoot[1..3] (trifoliate)
       └─ phytomer → internode → petiole → leaf × 3 + floral_bud
```

#### [NEW] `dataset/helios_dataset.py`
`HeliosPlantDataset(Dataset)`:
- `data_root`: Auto-detect `*_vis.jpeg` + `*_plant_*.xml` pairs in `build/output/`
- Images: Reuse existing `transforms` pipeline (256×256 normalized)
- **Camera Pose**: Read azimuth and elevation from `camera_positioning` in `params.json`
- **Per-DAP Separation**: Inject DAP as conditioning signal or record as metadata
- `__getitem__` → `{image, raw_image, nodes (N,11), adj_matrix, parent_indices, existence_mask, camera_pose, dap, organ_types}`

### Component 2: Model Architecture Updates

#### [MODIFY] `diffusion_based/models/graph_diffuser_3d.py`

**Core Change**: 7D → 11D node features + organ type conditioning

```python
# Before
class PlantGraphDiffuser3D:
    node_dim = 7  # (x, y, z, theta, phi, length, is_leaf)

# After
class PlantGraphDiffuser3D:
    node_dim = 11  # (x, y, z, length, radius, pitch, yaw, roll, organ_type x 4 one-hot)
```

1. Add **DAP Conditioning**:
   ```python
   self.dap_encoder = nn.Sequential(
       nn.Linear(1, embed_dim), nn.GELU(), nn.Linear(embed_dim, embed_dim)
   )
   ```
   - Inject temporal condition: `h_nodes = h_nodes + dap_emb`

2. Separate **Organ Type Prediction Head**:
   ```python
   self.organ_type_head = nn.Linear(embed_dim, 4)  # 4-class CE loss
   ```

3. Add **Shoot-Level Self-Attention** (optional):
   - Grouped attention mask based on shoot ID to attend more strongly among nodes in the same shoot

4. **Tune kNN Pruning k**: 8 → 16 (for complex structures)

### Component 3: Training Script Improvements

#### [MODIFY] `diffusion_based/training/train_diffusion_3d.py`

**Fix Core Issue**: Replace fixed 4 samples with standard DataLoader

```python
# Before (issue: 4 fixed samples)
four_samples = [dataset[i] for i in range(min(4, len(dataset)))]

# After (DataLoader batch training)
from torch.utils.data import DataLoader
loader = DataLoader(dataset, batch_size=16, shuffle=True, num_workers=4)
for epoch in range(epochs):
    for batch in loader:
        # Standard batch training
```

**Loss Function Updates**:
- Existing: `loss_coord3d` (MSE on xyz) + `loss_is_leaf` + `loss_scale` + `loss_snap3d`
- Additions:
  - `loss_organ_type = F.cross_entropy(pred_organ_logits, gt_organ_types)` (4-class)
  - `loss_radius = F.mse_loss(pred_x0[:,:,4], gt_nodes[:,:,4])` (organ radius)
  - `loss_orientation = F.mse_loss(pred_x0[:,:,5:8], gt_nodes[:,:,5:8])` (pitch, yaw, roll)
  - **Snap loss update**: Recompute kinematics using 11D coordinates

**Training Curriculum**:
```
Phase 1 (epochs 1-200):   Synthetic (Plant3DDataset) + HeliosDataset mix (3:1)
Phase 2 (epochs 201-500): HeliosDataset focus (1:3 ratio inverted)
Phase 3 (epochs 501+):    HeliosDataset exclusive + augmentation
```

**Checkpoint Saving**:
```python
# Save best validation loss and per-epoch checkpoints
if val_loss < best_val_loss:
    torch.save({"model": model.state_dict(), "epoch": epoch, "val_loss": val_loss},
               "diffusion_based/checkpoints/best_3d_model.pt")
```
